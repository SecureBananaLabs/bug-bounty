# API baseline and smoke benchmarks

Issue: https://github.com/SecureBananaLabs/bug-bounty/issues/30

Requires Node 22+. Install the API's JavaScript dependencies without lifecycle scripts:

```sh
cd apps/api
npm install --ignore-scripts --workspaces=false --no-audit --no-fund
cd ../..
npm run test:benchmark
npm run benchmark
npm run benchmark:smoke
```

No database, production token, or external service is required. The default command
starts the **real Express application on an ephemeral loopback port** and signs a
short-lived dedicated benchmark admin JWT with a freshly generated signing secret.
The secret and token are never saved. Services in this repository are currently
in-memory/placeholder implementations: payment results do not measure Stripe, and
search results do not measure PostgreSQL. These are application baselines only.
The Node load generator shares the application's process and CPU. Use a separate
process/host for infrastructure capacity studies.

`cases.mjs` inventories all 20 mounted API method/path combinations, including an
OAuth provider callback, authenticated admin metrics, and a real 16 KiB multipart
upload. JSON fixtures follow `packages/db/prisma/schema.prisma` and current Zod
validators, using synthetic identities, a roughly 1 KiB job description/message,
and a roughly 600-byte proposal. The route inventory test compares fixtures with
the mounted Express router and fails when routes are added without benchmark cases.

Copy `benchmarks/.env.benchmark.example` to root `.env.benchmark` for configuration.
`BENCHMARK_SECONDS` is duration **per endpoint**, 1–60 seconds; concurrency is
1–32. Defaults are 2 seconds/4 workers for baseline and 1 second/1 worker for
smoke. The suite measures endpoints sequentially with concurrent closed-loop
workers. In-flight requests finish after the deadline, and their time remains in
the sustained RPS denominator. Each request has a 5-second total deadline. All
response bodies are drained; headers are timed separately as TTFB. There is no
warmup exclusion: the initial request and connection setup remain in the sample.

The local app explicitly disables its 200-request/15-minute limiter to measure
handlers rather than a wall of HTTP 429 responses. `createApp()` and the production
server retain the limiter by default; authentication remains active in both modes.
The local suite mutates only disposable process memory. GET list fixtures initially
see empty in-memory lists; this does not model large production datasets. Repeat
runs start a fresh process and reset service state.

## External disposable staging (optional)

Only configure an origin you own and are authorized to load. Supply
`BENCHMARK_URL`, a dedicated short-lived admin `BENCHMARK_TOKEN`, and explicit
`BENCHMARK_ALLOW_WRITES=yes`. This creates users, jobs, proposals, payments,
reviews, messages, notifications, and uploads. **Never use production.** Provision
fixture IDs on staging as needed. The runner cannot seed a real database for you.
External rate limits remain unchanged: unexpected 429s count as errors and fail
the zero-error gate. No external benchmark was executed for the checked-in report.

## Reports and regression gate

`benchmarks/results/baseline.{json,md}` and `smoke.{json,md}` are generated by the
runner and include the actual environment, payload bytes, request counts, status
counts, duration, p50/p95/p99 latency, sustained/peak RPS, error rate, and TTFB
percentiles. Percentiles use nearest rank across completed attempts (including
errors); errors are transport failures or any status different from that fixture's
expected success code. Transport failures have no TTFB and are excluded only from
the TTFB distribution. Peak RPS is the busiest **complete** aligned one-second
window, not an extrapolated partial window. Sustained RPS includes error attempts.
Reports do not contain auth tokens, response bodies, or an external target URL.

`thresholds.json` holds the initial 250 ms p99 / 0% error ceiling and supports
per-endpoint overrides keyed by `METHOD /path`. Missing samples and violations
produce exit code 1 after both reports are written. Thresholds are a conservative
starting point, not a performance SLA. Tune them explicitly after collecting CI
runner baselines. The workflow executes existing API tests, benchmark tests, and
the low-concurrency smoke gate, then uploads reports even on failure. Hosted CI
itself remains pending until the PR is opened; the equivalent commands run locally.

The demo video replays actual terminal output from this contribution's local
validation; it is not a claim of production performance.
