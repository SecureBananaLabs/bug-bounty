TÍTULO: Bug: registerUser signs token with a different generated user id
DESCRIÇÃO: ## Description

The `registerUser` service currently generates a timestamp-based user ID twice: once for the returned `id` and once for the JWT `sub` claim. If the two `Date.now()` calls land on different milliseconds, the API can return a user whose token points at a different subject.

## Impact

- The returned registration response can contain an `id` that does not match the token subject.
- Authentication middleware or downstream lookups that trust `sub` may not match the newly-created user.
- The service creates an inconsistent auth state before persistence is implemented.

## Expected behavior

Generate the user ID once and reuse that same value for both the response object and the signed access token subject.

`apps/api/src/services/authService.js`
